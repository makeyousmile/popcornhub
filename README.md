# PopcornHub 🍿 — Сервис совместного просмотра видеоконтента

PopcornHub — высокопроизводительный сервис для синхронного просмотра медиаконтента семьями и дружескими компаниями в режиме реального времени. Платформа объединяет пользователей в группы, отображает текущую активность участников («Кто что смотрит сейчас») и обеспечивает демократичное (совместное) управление плеером с плавной коррекцией рассинхронизации.

---

## 🛠 Технологический стек

* **Бэкенд**: Go (Golang 1.22+)
* **Маршрутизация**: Стандартная библиотека `net/http.ServeMux` (встроенный роутинг методов и параметров путей без сторонних фреймворков)
* **Real-time WebSockets**: `github.com/gorilla/websocket` (с буферизованными каналами и защитой от блокировки медленными клиентами)
* **Основная БД**: MongoDB (официальный драйвер `go.mongodb.org/mongo-driver/v2/mongo`)
* **Кэш и шина событий**: Redis (Pub/Sub для межсервисной синхронизации между инстансами и временного хранения статусов присутствия с TTL)
* **Метрики и мониторинг**: Prometheus (`/metrics`) и структурированное логирование `log/slog`
* **Фронтенд**: Полнофункциональный SPA (HTML5, современный CSS, Vanilla JS) со встроенным видеоплеером, плавающими реакциями, групповым чатом и карточками активного просмотра
* **Контейнеризация**: Multi-stage `Dockerfile` (Alpine Linux) и `docker-compose.yml`

## 🏛 Архитектурные особенности

### 1. Модель данных в MongoDB
* `users`: хранение учетных записей, хешей паролей (bcrypt), ссылок на аватары и дат создания.
* `groups`: группы с инвайт-кодами (`FAM-9821`), владельцем и списком участников (`owner`, `admin`, `member`).
* `media_catalog`: библиотека фильмов и сериалов с метаданными (жанры, год, длительность) и потоковыми URL.
* `watch_rooms`: активные сессии совместного просмотра с состоянием плеера (`is_playing`, `position_sec`, `updated_at`, `last_action_by`) и списком активных зрителей.
* **Индексы**: уникальные индексы на `users.email` и `groups.invite_code`, индекс на `groups.members.user_id` и `watch_rooms.group_id`.

### 2. Система присутствия (Presence System — «Кто что смотрит»)
* Клиент подключается к шлюзу `/ws/presence?token=...`.
* Heartbeat-механизм: пинги от клиента каждые 15 секунд с автопродлением TTL ключа `popcornhub:presence:user:{user_id}` в Redis (45s).
* При старте или завершении просмотра событие мгновенно транслируется через Redis Pub/Sub согруппникам.
* В интерфейсе группы в реальном времени отображается карточка:
  > **Алексей смотрит «Интерстеллар»** [Присоединиться к просмотру 🚀]

### 3. Демократичный движок синхронизации (Collaborative Playback)
* Любой подключенный участник комнаты может запускать (`PLAY`), останавливать (`PAUSE`) и перематывать (`SEEK`) видео.
* Сервер рассчитывает актуальное время с учетом времени, прошедшего с последнего `PLAY`:
  $$\text{currentPosition} = \text{basePosition} + (t_{\text{now}} - t_{\text{updated}})$$
* **Двухуровневая коррекция рассинхронизации (Drift Correction)**:
  * Рассинхрон **0.3 – 2.0 сек**: плеер плавно регулирует скорость воспроизведения (`playbackRate = 1.05` или `0.95`) без прерывания звука.
  * Рассинхрон **> 2.0 сек**: мгновенный переход (`video.currentTime = syncTime`).
* **Rate Limiting**: алгоритм Token Bucket ограничивает частоту команд паузы/перемотки до 1 действия в 1.5 секунды от одного пользователя для защиты от спама.
* **Изоляция сбоев**: у каждого клиента персональный буферизованный канал на отправку; медленный или оборвавшийся сокет не блокирует других зрителей комнаты.

### 4. Интерактивность
* Текстовый онлайн-чат комнаты.
* Всплывающие анимированные эмодзи-реакции над видео (🍿, ❤️, 🔥, 😂, 👏, 😮, 😱).
* Системные уведомления в плеере (например, *«Мария поставила на паузу»*).

## 🚀 Запуск и развертывание

### Вариант 1: Запуск через Docker Compose (Рекомендуемый)

```bash
# Клонирование и переход в директорию
cd /root/popcornhub

# Сборка и запуск всех сервисов (Go App + MongoDB + Redis)
docker compose up -d --build

# Проверка логов
docker compose logs -f popcornhub
```

Сервис будет доступен по адресу: **http://localhost:8085**

### Вариант 2: Локальный запуск бинарника

1. Убедитесь, что MongoDB и Redis запущены (например, `docker compose up -d mongo redis`).
2. Запустите сервер:
```bash
./server
```
3. Откройте в браузере: **http://localhost:8085**

## 📡 Спецификация REST API

### Аутентификация
* `POST /api/v1/auth/register` — Регистрация нового пользователя (`name`, `email`, `password`)
* `POST /api/v1/auth/login` — Вход и получение JWT пары (Access + Refresh)
* `POST /api/v1/auth/refresh` — Обновление Access-токена по Refresh-токену
* `GET /api/v1/auth/me` *(Auth)* — Получение профиля текущего пользователя

### Группы
* `POST /api/v1/groups` *(Auth)* — Создать группу (`name`)
* `GET /api/v1/groups` *(Auth)* — Список групп текущего пользователя
* `GET /api/v1/groups/{id}` *(Auth)* — Детали группы
* `POST /api/v1/groups/join` *(Auth)* — Вступление в группу по инвайт-коду (`invite_code`)
* `GET /api/v1/groups/{id}/members` *(Auth)* — Список участников с аватарами и ролями
* `GET /api/v1/groups/{id}/presence` *(Auth)* — Текущие статусы присутствия участников

### Каталог медиа
* `GET /api/v1/media` *(Auth)* — Список доступных фильмов и потоков
* `GET /api/v1/media/{id}` *(Auth)* — Детали фильма
* `POST /api/v1/media` *(Auth)* — Добавить фильм в каталог

### Комнаты совместного просмотра
* `POST /api/v1/groups/{id}/room` *(Auth)* — Создать или получить активную комнату совместного просмотра фильма
* `GET /api/v1/rooms/{id}` *(Auth)* — Получить данные комнаты, группы и фильма

### Real-time WebSockets
* `GET /ws/presence?token={JWT}` — Шлюз присутствия (Heartbeat, live-уведомления)
* `GET /ws/rooms/{room_id}?token={JWT}` — Шлюз комнаты (Sync, Play/Pause/Seek, Chat, Reactions)

### Метрики и Healthcheck
* `GET /metrics` — Метрики Prometheus (RPS, задержки, активные сокеты)
* `GET /healthz` — Healthcheck
